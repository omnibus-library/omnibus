# Environment variables

What each variable does that its name doesn't say. [`.env.example`](../.env.example) is the catalog of every supported variable with an example value; this page holds the behaviour behind them. The dev shell's own variables (`CARGO_TARGET_DIR`, `PORT`, sccache) and the three every dev loop touches are in [rule 01](../.claude/rules/01-dev-environment.md).

Adding a variable: document it here and in `.env.example` in the same change.

## Reference

- `OMNIBUS_DEV_SEED_USER=username:password` — creates a named admin user on server boot if absent, and gives a newly created one a private "Kobo library" smart shelf of every EPUB, CBZ and PDF with Kobo sync on. Dev convenience for `ui-validate` and parallel agents; never set in production. Password must satisfy `db::auth` validation (≥10 chars, not in `COMMON_PASSWORDS`). It is also the login `mock-kobo serve`/`tui` auto-wires a device with.
- `OMNIBUS_E2E_RELEASE=1` — makes `just e2e-ci` bundle `--release`, as CI's E2E job does. The default is a debug bundle that shares `dx serve`'s incremental artifacts: a few seconds when nothing changed, but with debug assertions on, so a failure only CI shows wants this. A release bundle builds apart from the dev server and takes far longer.
- `OMNIBUS_DEV_DISABLE_RATE_LIMITS=1` — turns off all five per-IP limiters (auth, search, image uploads, book uploads, OPDS Basic) so per-IP throttling never answers `429`; the per-account lockout stays on (5 wrong passwords → `429` on the next correct-password login, `403` on OPDS). Honoured only in debug builds: a release build ignores it and logs a WARN. Read once at boot in `launch()` (`server/src/main.rs`) and decided by `RateLimits::at_boot` (`server/src/rate_limit.rs`), so changing it needs a server restart. `.env.example` sets it; never set in production.
- `OMNIBUS_SECURE_COOKIES=0` — disables the `Secure` flag on session cookies. The default is `true` (secure-by-default). Browsers treat `http://localhost` as a secure context, so the Nix dev shell does not need this override; only set `0` when serving plain `http://` from a non-localhost origin (e.g. an IP-based dev server on a LAN). Never set in production.
- `EBOOK_LIBRARY_PATH` / `AUDIOBOOK_LIBRARY_PATH` — pre-seed library paths via the `seed_settings_from_env` boot hook (runs every boot; overwrites the settings row with BOTH values, so set both together or neither). For CI / Docker / dev-up; leave unset in production.
- `HARDCOVER_API_KEY` — account-level Hardcover Bearer token for F3.3 "Readers also enjoyed" suggestions. Unlike the library paths, the **Settings page is the source of truth**: the `seed_hardcover_key_from_env` boot hook seeds this value only when none is saved (settings wins thereafter), and `effective_hardcover_api_key` falls back to it when settings is empty. Server-wide, never per-user; leave unset to keep suggestions disabled. A configured key also adds Hardcover as the **last** rung of the check-in metadata ladder (`search_provider_by_isbn`/`_by_title`) — skipped entirely when unset, tried only after Open Library and Google Books come up empty, and never allowed to surface an error; in exchange it's the one provider that carries a series statement natively.
- `GOOGLE_BOOKS_API_KEY` — API key for the Google Books rung of the check-in ISBN lookup ladder. The ladder order is **key-dependent** (`search_provider_by_isbn`/`_by_title`): with a key configured Google Books leads and Open Library is the fallback; keyless, Open Library leads and Google Books is the fallback. Keyless Google Books requests share an anonymous daily quota that a self-hosted instance exhausts almost immediately (HTTP 429), so it's only a dependable primary once keyed. Free, no billing account — see [.env.example](../.env.example) for the console steps. Same source-of-truth model as the Hardcover key: the **Settings page is the source of truth** — the `seed_google_books_key_from_env` boot hook seeds this value only when none is saved (settings wins thereafter), and `effective_google_books_api_key` falls back to it when settings is empty. Server-wide, never per-user. Sent as an **`X-goog-api-key` header**, never in a URL — a `reqwest::Error` renders the request URL in its `Display` but never a header, so no fallible step has a credential to write into `omnibus.log`. Both Google Books clients (`metadata_lookup/providers/googlebooks.rs` and `book_summary/googlebooks.rs`) do this; `http::strip_url` is now noise-reduction rather than the credential guard, so a provider added with a key in its URL must move the key to a header rather than adding a `strip_url` call.
- `SMTP_HOST` / `SMTP_PORT` / `SMTP_SECURITY` / `SMTP_USERNAME` / `SMTP_PASSWORD` / `SMTP_FROM_EMAIL` — F4.3 Send-to-Kindle SMTP relay. Same source-of-truth model as the Hardcover key: `seed_smtp_from_env` seeds the config only when no host is saved (Settings page wins thereafter), and `effective_smtp_config` falls back to the env vars when settings is empty. `SMTP_HOST` + `SMTP_FROM_EMAIL` are required; port defaults to 587 and security to `starttls` (`tls` for implicit TLS on 465). Server-wide; leave unset to keep Send-to-Kindle disabled. (A user's own `kindle_email` lives per-account on the `/account` page, not here.)

- `OMNIBUS_EXPLORE_URL` / `OMNIBUS_EXPLORE_ADMIN` — the persistent instance the [agentic-exploration](../.claude/skills/agentic-exploration/SKILL.md) swarm drives, and the single credential that system persists (`user:password`). Per-agent accounts keep **stable usernames** because provenance ownership is keyed on the actor — a fresh account each run would orphan every book earlier runs uploaded — while their passwords are rotated at each invocation through the admin reset endpoint and never stored. Point it at a throwaway instance only: agents upload, edit metadata, merge, and delete. `OMNIBUS_EXPLORE_JOURNAL_DIR` is where run journals live, and it matters more than it looks: the journal is the ownership ledger, so it must sit **outside** the worktrees — `.claude/runtime/` is gitignored and per-worktree, so leaving journals there lets a `wt switch` silently orphan every book an agent ever uploaded. Optional siblings `OMNIBUS_EXPLORE_SSH_HOST`, `OMNIBUS_EXPLORE_REMOTE_DIR`, `OMNIBUS_EXPLORE_SNAPSHOT_DIR`, `OMNIBUS_EXPLORE_SNAPSHOT_KEEP` tell `scripts/explore/snapshot.sh` where the instance host lives and how many tarballs to keep, and `OMNIBUS_EXPLORE_REMOTE_LOG_DIR` (default `cache/data/logs`, relative to the remote dir) tells `scripts/explore/report.py` where that instance's JSON log sink is — it follows the instance's own `OMNIBUS_DATA_DIR`. `OMNIBUS_EXPLORE_PORT_BASE` (default 9223) and `OMNIBUS_EXPLORE_PORT_WINDOW` (default 32) are the browser driver's port range: agent n listens on base + n − 1, and `driver.sh down` / `status` sweep the whole window. `OMNIBUS_EXPLORE_MOCK_KOBO` (a built `mock-kobo` for `scripts/explore/kobo.sh up` to start; unset, `up` builds one with cargo) and `OMNIBUS_EXPLORE_KOBO_DIR` (default `.claude/runtime/explore/kobo`; a relative path is taken from the repo root) are the Kobo lane's: one fake Kobo per agent, each device's `state.json` holding its token, so every file there is owner-only. `OMNIBUS_EXPLORE_KOBO_STOP_TICKS` (default 50, 0.2 s each) is how long `kobo.sh down` waits for a device to exit before killing it; only the tests set it. `OMNIBUS_IOS_KEEP_CONTAINER=1` makes `scripts/explore/ios.sh up` keep the simulator's app container instead of uninstalling first (the default, so a run never starts signed in as the previous run's iOS actor). The three required vars are the only ones the skill prompts for: `scripts/explore/env.sh check` names whichever has no value and `env.sh set <KEY> <value>` writes the answer back into `.env`, so a run is never started on an invented URL or credential.

- `OMNIBUS_MCP_URL` / `OMNIBUS_MCP_USERNAME` / `OMNIBUS_MCP_PASSWORD` — the instance and account the `omnibus-mcp` binary (the `mcp/` crate's read-only MCP stdio server) logs in as; the matching CLI flags (`--url`/`--username`/`--password`) win over these. Credentials, not a token, so the binary can re-login unattended after the 7-day bearer idle expiry. See [.env.example](../.env.example) and the crate docs in `mcp/src/lib.rs`.

- `OMNIBUS_MOCK_KOBO_URL` / `OMNIBUS_MOCK_KOBO_TOKEN` / `OMNIBUS_MOCK_KOBO_STATE` — the server origin, device token and state file `mock-kobo serve`/`tui` (the `mock-kobo/` crate's fake e-reader) uses; the matching flags (`--url`/`--token`/`--state`) win over these. Unset, it follows `.claude/runtime/port` and auto-wires a "Mock Kobo" device as the `OMNIBUS_DEV_SEED_USER` admin, but only against a local server (`localhost`, `127.0.0.0/8`, `::1`) and again if the dev server moves; elsewhere pass a token. See [.env.example](../.env.example) and `mock-kobo --help`.

- `RUST_LOG` — console log filter (tracing `EnvFilter` syntax). The server owns its subscriber (`init_tracing` in `server/src/logging.rs`), so this works under both `cargo run -p omnibus` and `dx serve`. Default when unset: `info,omnibus=debug` — one INFO line per HTTP request from `server/src/request_log.rs`: the span carries `method`, `path` (Kobo token segment redacted), `version`, `client_ip` (via `rate_limit::client_ip`, so `X-Forwarded-For` counts only under `OMNIBUS_TRUST_FORWARDED_FOR`), `range` and `user_agent`; the `finished processing request` event carries `status`, `latency` (time to headers, `"{n} ms"`), `content_length` and `content_range`; a second `response body finished` event carries `stream_duration_ms`, the time the body actually took — what a two-hour range stream reports instead of "2 ms". Query strings are never logged (media routes carry `?token=`). The same filter gates both the stderr and the on-disk JSON sinks.
- `OMNIBUS_LOG_DIR` — directory for the durable on-disk JSON logs. `init_tracing` layers a non-blocking daily-rolling JSON file sink (`omnibus.log.YYYY-MM-DD`) alongside the human-readable stderr stream; its `WorkerGuard` is held in `main` for the process lifetime so buffered records flush on shutdown. Used verbatim when set; otherwise `$OMNIBUS_DATA_DIR/logs` (default `./data/logs`). Same absolute-path guidance as `OMNIBUS_DATA_DIR`.

**Security-sensitive (never set casually in production):**

- `OMNIBUS_INITIAL_ADMIN=username` — promotes the named user to admin on **every** boot while set. One-time account recovery only — UNSET IMMEDIATELY AFTER USE.
- `OMNIBUS_TRUST_FORWARDED_FOR=1` — trust the client `X-Forwarded-For` as the per-IP rate-limit key, keyed on the RIGHTMOST hop (the one the nearest proxy appended). This assumes exactly ONE trusted proxy in front of Axum — there is no hop-count knob — so behind a chain (CDN → nginx → omnibus) the rightmost hop is the inner proxy and every client shares its bucket. MUST NOT be set unless a trusted reverse proxy strips inbound `X-Forwarded-For`; on a directly-exposed deployment it lets any client spoof a fresh bucket and bypass the login throttle (credential stuffing).
- `OMNIBUS_METRICS_TOKEN=<random>` — bearer token a Prometheus scraper must present to read `GET /metrics`. That route sits outside `/api/*`, so `require_auth` never gates it and this token is the only thing in front of ~76 KB of endpoint topology. Unset or blank (the default) means `/metrics` answers **404** and `metrics::warn_if_disabled` logs one startup WARN; a wrong or missing bearer is 401.

Optional storage overrides:
- `OMNIBUS_COVERS_DIR` — where cover image files are stored (default `./covers`). Set to an absolute path on real deployments so covers don't land next to the binary and disappear on redeploy.
- `OMNIBUS_THUMBS_DIR` — where WebP thumbnails are cached (default `./thumbs`)
- `OMNIBUS_THUMBS_CAP_BYTES` — eviction cap in bytes (default 1 GiB; thumbnails are lossy WebP, so a 1,600-book library caches ~50 MB)
- `OMNIBUS_JOURNAL_IMAGES_DIR` — where images embedded in journal entries are stored, used verbatim when set; otherwise `$OMNIBUS_DATA_DIR/journal-images`. Durable user data (not a regenerable cache) — same absolute-path guidance as covers, which is why the Docker image points it at `/config/journal-images` rather than letting it fall into the regenerable `/cache` volume. `journal_images::relocate_legacy_journal_images` moves anything left in the `$OMNIBUS_DATA_DIR` default here once at boot, so an instance predating that default doesn't lose its images to a `/cache` wipe.
- `OMNIBUS_MAX_UPLOAD_BYTES` — max accepted size for an "add your own books" upload, as both the upload routes' body limit and a per-file check (default 1 GiB)
- `OMNIBUS_PDF_PARSE_MAX_BYTES` — largest PDF either parser in `db::pdf` will load at all; past it a file indexes from its filename with no cover, page count, or text (default 512 MiB)
- `OMNIBUS_PDF_TEXT_MAX_BYTES` — largest PDF the text extractor (`db::pdf`, backing the content index, the chapter list, and the word count) will load; larger files still index with cover, metadata, and page count from the lazy parser (default 128 MiB)

HLS audiobook transcode cache (read by `db::hls`):
- `OMNIBUS_DATA_DIR` — base data dir; HLS segments live under `$OMNIBUS_DATA_DIR/hls/` (default `./data`)
- `OMNIBUS_HLS_CAP_BYTES` — HLS cache eviction cap in bytes (default 5 GiB)
- `OMNIBUS_HLS_TRANSCODE_TIMEOUT_SECS` — ffmpeg watchdog per book in seconds (default 1800)
- `OMNIBUS_FFMPEG_PATH` — explicit ffmpeg path; otherwise ffmpeg must be on `$PATH`

Kobo KEPUB conversion (read by `db::kepub`, for the "Send to Kobo" download):
- `OMNIBUS_KEPUBIFY_PATH` — explicit kepubify path; otherwise kepubify must be on `$PATH`. Absent → download falls back to plain EPUB with a one-time startup warning. Bundled in the `.#web` shell and the release image.
- `OMNIBUS_KEPUB_DIR` — directory for the KEPUB cache, used verbatim when set; otherwise defaults to `$OMNIBUS_DATA_DIR/kepub/`. Purely a regenerable cache (safe to delete, rebuilt on next download).

Calibre format conversion (read by `db::convert`):
- `OMNIBUS_EBOOK_CONVERT_PATH` — explicit path to Calibre's `ebook-convert`; otherwise `ebook-convert` must be on `$PATH`. Calibre is optional: an unresolved binary logs exactly one startup warning (`convert::warn_if_unavailable`, `OnceLock`-gated) and leaves conversion disabled rather than failing the boot. Same source-of-truth model as the Hardcover key — the **Settings page wins**: `seed_ebook_convert_path_from_env` seeds the `ebook_convert_path` settings row only when none is saved, and `effective_ebook_convert_path` resolves settings → this var → the bare `ebook-convert` name on `$PATH`. Server-wide, never per-user. Unlike kepubify, Calibre is **not** bundled in the Nix shells or the release image — install it separately.

Format-conversion worker task (`#948`, read by `db::convert::{execute,fs}`, driven by `worker::Task::ConvertFormat` under a `max(1, num_cpus / 2)` concurrency cap mirroring the HLS transcode semaphore):
- `OMNIBUS_CONVERT_DIR` — directory for the converted-format output cache (`<dir>/<book_id>.<target_format>`), used verbatim when set; otherwise defaults to `$OMNIBUS_DATA_DIR/convert`. Purely a regenerable cache (safe to delete, rebuilt on next conversion), written via an atomic temp-then-rename. Set to an absolute path on real deployments (same guidance as `OMNIBUS_KEPUB_DIR`).
- `OMNIBUS_CONVERT_TIMEOUT_SECS` — wall-clock watchdog per conversion job in seconds (default 600); exceeding it reports `ConvertError::Timeout`. `ebook-convert` is far lighter than an ffmpeg transcode, so the default is more modest than `OMNIBUS_HLS_TRANSCODE_TIMEOUT_SECS`'s 1800 — increase for very large books on slow hardware.

Export-with-overrides EPUB cache (read by `db::epub_rewrite`, for the "Send to Kobo" + plain EPUB download when a book has overrides):
- `OMNIBUS_EXPORT_EPUB_DIR` — directory for the override-baked EPUB cache, used verbatim when set; otherwise defaults to `$OMNIBUS_DATA_DIR/export-epub/`. Purely a regenerable cache (safe to delete, rebuilt on next export), invalidated on `books.last_modified` (bumped on every override save).
- `OMNIBUS_EXPORT_EPUB_CAP_BYTES` — eviction cap in bytes (default 5 GiB), same shape as `OMNIBUS_THUMBS_CAP_BYTES`/`OMNIBUS_HLS_CAP_BYTES` but FIFO by last-rewrite mtime rather than LRU (no cache-hit touch, since this cache is only written on an explicit export/download, not every page view).

- `OMNIBUS_VERSION` — the running release tag (e.g. `v0.8.9`), read once at boot and returned as the `version` field on `GET /api/_health`; the mobile "You" screen fetches it there to show the server's release alongside the app's own compile-time build version (F-1055, `server::backend::app_version`). Also read at **compile time** via `option_env!` by `omnibus_frontend::version::app_version` so the web user-menu version line and a mobile build's own "App version" line report the real tag instead of the crate's pinned `0.1.0`. Baked into the Docker image build-arg (`Dockerfile`, `.github/workflows/docker.yml`) and into the TestFlight build env (`.github/workflows/testflight.yml`, mirroring its already-resolved `MARKETING_VERSION`). Leave unset for local dev — the server reports `"dev"` and the frontend falls back to `CARGO_PKG_VERSION`.

- `OMNIBUS_REACT_DIR` — opt-in: a `vite build --base=/react/` output (`frontend-js/dist`, built by `pnpm --dir frontend-js run build`). When it holds an `index.html`, the server also serves the React client at `/react/` (`backend::react_ui`), beside the Dioxus UI on the same origin; a client route gets the app shell and a missing asset a 404. Unset (the default) mounts nothing; a directory without `index.html` logs one WARN at boot. Read once at boot.
